# Microinteractions

---

# Purpose

Microinteractions are the smallest moments in the F.I. Forgot experience.

They are often invisible when executed well, yet they profoundly influence how the product feels.

Every tap.

Every click.

Every hover.

Every confirmation.

Every tiny piece of feedback should quietly reinforce that the user is interacting with a thoughtful Relationship Concierge.

Microinteractions should reduce uncertainty, increase confidence, and create an experience that feels polished without ever feeling playful for the sake of being playful.

Every microinteraction should answer one question:

> **"Would a world class Relationship Concierge respond this way?"**

---

# Microinteraction Philosophy

Users should never wonder whether something happened.

The interface should always acknowledge an action.

Feedback should feel immediate.

Gentle.

Human.

Predictable.

Microinteractions should never compete with content.

They should support it.

The user should feel guided rather than entertained.

---

# Emotional Goals

Every interaction should reinforce:

Trust

Warmth

Confidence

Calmness

Clarity

Premium craftsmanship

Thoughtfulness

The experience should never feel mechanical or robotic.

---

# Core Principles

## Immediate Feedback

Every meaningful interaction receives immediate acknowledgment.

Waiting without feedback creates uncertainty.

---

## Subtlety

The smallest interaction should create the smallest response.

Avoid exaggerated reactions.

---

## Predictability

The same interaction always behaves the same way.

Consistency builds trust.

---

## Continuity

Changes should feel connected.

Elements should never appear to teleport.

---

## Accessibility

Every interaction must remain understandable without relying solely on motion, color, or sound.

---

# Feedback Principles

Every user action should produce one of the following:

Visual feedback

Motion feedback

Textual feedback

Haptic feedback when supported

Never leave important actions without acknowledgment.

---

# Hover Behavior

Desktop only.

Hover indicates possibility, not commitment.

Examples:

Buttons darken slightly.

Cards lift subtly.

Icons increase contrast.

Links underline or change color.

Hover should never trigger major interface changes.

---

# Press Behavior

Every press should feel responsive.

Buttons compress slightly.

Cards acknowledge selection.

Icons react immediately.

Maximum duration:

100 milliseconds.

The interface should feel connected to the user's touch.

---

# Focus Behavior

Keyboard focus must always be visible.

Focus indicators should:

Use the brand accent color.

Meet accessibility contrast requirements.

Remain visible until focus changes.

Never rely on browser defaults unless they meet design standards.

---

# Active States

Active elements should clearly communicate current context.

Examples:

Selected navigation.

Active filters.

Current tab.

Expanded section.

Active states should persist until context changes.

---

# Disabled States

Disabled controls should remain understandable.

Users should know:

What the control does.

Why it is unavailable.

Avoid reducing opacity so much that controls become unreadable.

Whenever appropriate, explain how to enable the action.

---

# Button Interactions

## Hover

Background darkens slightly.

---

## Press

Scale to 98 percent.

---

## Release

Smooth return.

---

## Loading

Spinner replaces icon or label gracefully.

Button width remains fixed.

---

## Success

Soft checkmark.

Brief confirmation.

No dramatic celebration.

---

# Icon Interactions

Icons should respond only when interactive.

Responses include:

Opacity adjustment.

Color transition.

Subtle scale.

Never rotate icons unnecessarily.

Never bounce.

---

# Card Interactions

Cards represent meaningful information.

They should feel tangible.

Hover:

Small elevation.

Press:

Very slight compression.

Selection:

Border accent.

Gentle background transition.

Cards should never bounce or tilt.

---

# Navigation Interactions

Changing sections should feel continuous.

Active destination updates smoothly.

Navigation should never flash.

Transitions should preserve orientation.

Users should always know where they are.

---

# Input Interactions

Inputs should acknowledge attention.

Focus:

Border transition.

Visible focus ring.

Placeholder softens.

Typing should never trigger distracting animations.

---

# Textarea Interactions

Textarea fields should expand naturally when appropriate.

Character count should update quietly.

Autosave should occur without interrupting writing.

Saving indicators should remain subtle.

---

# Dropdown Interactions

Menus open smoothly.

Selected items update immediately.

Closing should preserve context.

Dropdowns should never jump across the screen.

---

# Checkbox Interactions

Selection should feel confident.

Checkmark appears smoothly.

Label remains stable.

Checkboxes should not bounce.

---

# Radio Button Interactions

Selection should clearly indicate exclusivity.

Inner indicator expands smoothly.

Previous selection fades naturally.

---

# Toggle Interactions

Switch movement should mirror physical switches.

Thumb slides.

Background transitions.

State label updates immediately.

---

# Search Interactions

Search should encourage exploration.

Focus expands naturally.

Results appear progressively.

Empty results provide guidance rather than failure.

Loading remains subtle.

---

# Timeline Interactions

Timeline entries should preserve reading position.

Expanding memories should not cause large layout jumps.

New memories should fade into place.

Scrolling should feel uninterrupted.

---

# Memory Interactions

Opening a memory should feel like opening a journal entry.

Images fade naturally.

Supporting information appears progressively.

Closing returns the user to the same position.

---

# Recipient Interactions

Selecting a recipient should reinforce personal connection.

Identity remains visible during transitions.

Relationship context appears naturally.

Primary actions remain obvious.

---

# Brownie Points Interactions

Brownie Points should acknowledge progress quietly.

Small number increase.

Soft highlight.

Warm color transition.

No slot machine behavior.

No coin animations.

No exaggerated rewards.

---

# Relationship Health Interactions

Health indicators should evolve gently.

Changes animate smoothly.

Improvement should feel encouraging.

Declines should avoid creating anxiety.

---

# Autopilot Interactions

Turning Autopilot on should feel reassuring.

Confirmation appears immediately.

Brief success message.

Small visual confirmation.

No dramatic effects.

---

# Notification Interactions

Notifications should feel like gentle reminders.

Arrival should never interrupt the user.

Dismissal should remain easy.

Notifications should disappear naturally when appropriate.

---

# Success Confirmations

Successful actions deserve acknowledgment.

Examples:

Card scheduled.

Profile updated.

Memory added.

Confirmation should include:

Visual cue.

Brief message.

Optional icon.

No modal interruption unless required.

---

# Error Feedback

Errors should feel supportive.

Explain:

What happened.

Why it happened.

What the user should do next.

Avoid technical language.

Avoid blame.

---

# Inline Validation

Validation should prevent mistakes early.

Prefer helpful guidance over correction.

Use encouraging language.

Validation should appear close to the relevant field.

---

# Copy to Clipboard Behavior

Copy actions should receive immediate confirmation.

Example:

"Copied."

Confirmation should disappear automatically.

No additional dialogs.

---

# Drag and Drop Interactions

Dragging should preserve context.

Drop targets should highlight clearly.

Objects should move naturally.

Never create confusing movement.

---

# Swipe Interactions

Swipe gestures should supplement navigation.

Never replace primary navigation.

Every swipe action should have a visible alternative.

---

# Long Press Behavior

Long press should reveal secondary actions only when appropriate.

Avoid hiding essential functionality behind long presses.

---

# Keyboard Interactions

Every interactive element must support keyboard navigation.

Focus order should follow reading order.

Enter activates primary actions.

Space activates buttons where appropriate.

Escape closes overlays.

Arrow keys navigate logical collections.

Keyboard users should receive the same feedback as mouse users.

---

# Mouse Interactions

Cursor changes should communicate interactivity.

Hover effects should remain subtle.

Dragging should feel precise.

Scrolling should remain smooth.

---

# Touch Interactions

Touch should feel direct.

Controls should respond immediately.

Avoid delayed feedback.

Respect minimum touch target sizes.

Prevent accidental activation.

---

# Haptic Feedback Guidelines

Where supported by the operating system:

Use light haptic feedback for:

Successful actions.

Toggle changes.

Long press confirmation.

Avoid strong haptics.

Avoid repeated vibration.

Haptics should reinforce confidence, not demand attention.

---

# Sound Philosophy

Sound is optional.

The product should never rely on audio.

If sounds are introduced:

Keep them subtle.

Warm.

Natural.

Never gamified.

Never startling.

Respect system sound preferences.

---

# Delight Moments

Moments of delight should be rare.

Reserve them for meaningful milestones.

Examples:

First relationship completed.

First handwritten card sent.

Major anniversary remembered.

Long term Relationship Health improvement.

Delight should celebrate thoughtfulness, not usage.

---

# Accessibility Considerations

Every microinteraction must remain accessible.

Support:

Keyboard navigation.

Screen readers.

Reduced motion.

High contrast modes.

Touch accessibility.

Never communicate meaning through animation alone.

Never depend solely on color.

---

# Consistency Rules

Buttons always behave the same.

Cards always behave the same.

Forms always behave the same.

Navigation always behaves the same.

Users should build confidence through repetition.

Consistency is more valuable than novelty.

---

# Microinteraction Hierarchy

Priority order:

1. Feedback

2. Clarity

3. Accessibility

4. Emotional reassurance

5. Polish

6. Delight

Delight should never come at the expense of usability.

---

# Anti Patterns

Never use:

Unexpected movement.

Confetti for routine actions.

Bouncing buttons.

Rotating icons without meaning.

Large hover effects.

Aggressive animations.

Constant pulsing.

Flashing indicators.

Delayed feedback.

Invisible focus states.

Hover only interactions.

Gesture only functionality.

Overlapping confirmations.

Multiple simultaneous notifications.

Reward mechanics that resemble gambling.

Interactions that interrupt writing.

Technical error messages.

Blame oriented messaging.

Visual noise.

---

# Review Checklist

Before approving any microinteraction, verify:

□ Does the interaction provide immediate feedback?

□ Does it reduce uncertainty?

□ Does it feel calm?

□ Is the response proportional to the action?

□ Is the interaction consistent with similar components?

□ Does it preserve context?

□ Is keyboard support complete?

□ Is touch behavior intuitive?

□ Does it support accessibility requirements?

□ Does it respect reduced motion preferences?

□ Are confirmations clear but unobtrusive?

□ Are errors supportive rather than alarming?

□ Does it reinforce trust?

□ Does it feel thoughtfully crafted?

□ Would the user describe the interface as polished rather than animated?

□ Does every interaction reinforce the feeling of a premium Relationship Concierge?

If the answer to any question is no, the microinteraction should be revised before implementation.
