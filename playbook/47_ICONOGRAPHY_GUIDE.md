# F.I. Forgot Iconography Guide

---

# Purpose

This document defines the iconography system used throughout F.I. Forgot.

Icons exist to improve understanding.

They should never exist simply to decorate the interface.

The best icons disappear into the experience.

Users should understand them immediately without needing to think.

Every icon should reinforce the feeling of a premium Relationship Concierge.

---

# Icon Philosophy

Icons support words.

They do not replace words.

The interface should remain understandable even if every icon disappeared.

Icons improve scanning.

They reduce cognitive effort.

They help users find information more quickly.

They should never become the primary method of communication.

---

# Emotional Goals

Icons should feel:

* Calm

* Friendly

* Refined

* Professional

* Timeless

* Human

They should never feel:

* Aggressive

* Cartoonish

* Technical

* Futuristic

* Playful for the sake of being playful

Relationships are emotional.

Icons should quietly support that experience.

---

# Visual Style

Use a single icon family throughout the application.

Every icon should share:

* Similar proportions

* Consistent stroke width

* Matching corner treatment

* Identical visual weight

* Consistent optical sizing

Icons should feel like they were designed together.

Never mix icon libraries.

---

# Design Language

Icons should be:

Simple

Recognizable

Balanced

Minimal

Readable at small sizes

Avoid unnecessary detail.

An icon should communicate its meaning in less than a second.

---

# Outlined vs Filled

Outlined icons are the default.

Filled icons are reserved for:

Selected navigation items.

Active states.

Important status indicators.

Never mix outlined and filled versions of the same icon within the same context.

---

# Stroke Weight

Use one consistent stroke weight throughout the application.

Icons should neither appear too thin nor too bold.

Visual consistency is more important than artistic expression.

---

# Corner Treatment

Icons should use soft geometry.

Sharp angles should be avoided unless the metaphor requires them.

Rounded forms reinforce warmth and approachability.

---

# Optical Balance

Icons should appear visually equal.

Not mathematically equal.

Every icon should feel balanced regardless of its shape.

---

# Icon Sizes

Use shared sizing tokens.

Typical categories:

Extra Small

Small

Medium

Large

Extra Large

Hero

Do not invent intermediate sizes.

---

# Color Usage

Icons inherit semantic colors.

Primary actions use primary colors.

Supporting icons use secondary text colors.

Success icons use success colors.

Warning icons use warning colors.

Error icons use error colors.

Icons should never introduce new colors.

---

# Placement

Icons should align consistently.

Maintain equal spacing between icon and text.

Avoid placing icons where they do not improve comprehension.

Whitespace is often more valuable than another icon.

---

# Icons With Text

Whenever possible:

Icon first.

Text second.

The icon supports the label.

Never rely on icons alone for important actions.

---

# Interactive Icons

Clickable icons should clearly communicate interaction.

Hover states should be subtle.

Pressed states should feel responsive.

Focus states should remain visible.

Interactive icons must meet accessibility requirements.

---

# Decorative Icons

Decorative icons should be rare.

If removing the icon does not change understanding, question whether it belongs.

Minimalism is preferred.

---

# Navigation Icons

Navigation icons should communicate destinations immediately.

Examples include:

Home

People

Timeline

Cards

Business

Notifications

Settings

Help

The same icon should always represent the same destination.

Never change icon meanings between screens.

---

Appropriate icons include:

Person

Heart

Conversation

Photo

Timeline

Celebration

Gift

Calendar

Story

Avoid stereotypes.

Avoid gender specific assumptions.

People come first.

---

# Memory Icons

Memory related icons should reinforce storytelling.

Examples:

Photo

Conversation

Star

Book

Moment

Smile

Location

Music

Food

Travel

Icons should suggest memories, not databases.

---

# Card Creation Icons

Card creation icons should support creativity.

Examples:

Card

Pen

Envelope

Draft

Edit

Preview

Delivery

These icons should communicate warmth.

Not automation.

---

# Business Concierge Icons

Business experiences remain relationship focused.

Appropriate icons include:

Handshake

Briefcase

Building

People

Calendar

Conversation

Gift

Recognition

Partnership

Avoid overly corporate symbols.

Avoid charts unless absolutely necessary.

---

# Notification Icons

Notifications should communicate importance calmly.

Information

Reminder

Success

Warning

Update

Delivery

Never use alarming visual language unless truly necessary.

---

# Status Icons

Status icons should remain consistent.

Success

Warning

Information

Error

Pending

Completed

Each status should always use the same icon throughout the application.

---

# Empty State Icons

Empty states may use icons or illustrations.

Icons should remain optimistic.

Examples:

Calendar

Notebook

Memory

Conversation

Photo

People

They should encourage action.

Not emphasize absence.

---

# Search Icons

Search interactions should remain familiar.

Use universally recognized search metaphors.

Avoid creative reinterpretations.

Familiarity reduces friction.

---

# Settings Icons

Settings icons should remain conventional.

Users should immediately recognize:

Notifications

Privacy

Billing

Appearance

Accessibility

Security

Do not invent custom metaphors.

---

# Accessibility

Icons must never be the only way to communicate meaning.

Every actionable icon requires:

Accessible labels.

Keyboard accessibility.

Visible focus states.

Sufficient contrast.

Decorative icons should be hidden from assistive technologies.

Meaningful icons should have descriptive labels.

---

# Icon Animation

Icons should animate only when it improves understanding.

Examples:

Loading indicator.

Success confirmation.

Expandable sections.

Notifications.

Animation should remain subtle.

Avoid spinning icons unless representing loading.

Avoid bouncing.

Avoid pulsing indefinitely.

---

# Custom Icons

Custom icons should only be created when no universally understood icon exists.

Every custom icon should:

Match the system.

Share stroke width.

Share proportions.

Share corner treatment.

Be documented before implementation.

---

# Illustration vs Icon

Icons communicate actions.

Illustrations communicate emotion.

Never replace illustrations with oversized icons.

Never use illustrations as interface controls.

Each has a different purpose.

---

# Things To Avoid

Avoid emoji as interface icons.

Avoid multiple icon styles.

Avoid decorative icons.

Avoid inconsistent stroke widths.

Avoid unnecessary icon badges.

Avoid icons without labels.

Avoid tiny touch targets.

Avoid icons used purely because space is available.

Avoid mixing sharp and rounded icon styles.

Avoid icons that require explanation.

Avoid visual clutter.

---

# Icon Consistency Checklist

Before shipping an icon:

Does it improve understanding?

Is it immediately recognizable?

Does it match the rest of the icon family?

Is it the correct size?

Does it use semantic color?

Does it align correctly?

Does it have an accessible label?

Could the interface work without it?

If yes, is the icon still providing value?

Does it feel like part of a premium Relationship Concierge experience?

If not, redesign it.

---

# Final Principle

Icons should quietly support every interaction without demanding attention.

They guide.

They clarify.

They simplify.

When users think back on F.I. Forgot, they should remember the people they celebrated, not the icons they clicked.

That is the iconography system of F.I. Forgot.
