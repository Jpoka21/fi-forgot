# F.I. Forgot Executive Summary

> **This document is the first document every designer, engineer, product manager, AI coding assistant, and contributor should read before opening any other file in the playbook.**

This document summarizes the philosophy, principles, and non negotiable rules that define F.I. Forgot.

It is not a replacement for the rest of the playbook.

It is the foundation that ties every document together.

---

# Mission

F.I. Forgot exists to help people become more thoughtful in the relationships that matter most.

Everything we build should make meaningful relationships stronger.

Greeting cards are simply the first expression of that mission.

The product is building toward becoming the world's most trusted Relationship Concierge.

---

# Vision

We believe people rarely stop caring.

They simply become busy.

Life becomes complicated.

Important dates are forgotten.

Conversations fade.

Memories disappear.

Small opportunities to strengthen relationships are missed.

Technology should not replace thoughtfulness.

Technology should quietly support it.

Our long term vision is to build software that helps people consistently show up for the people they love and the people they work with.

---

# Product Identity

F.I. Forgot is not a greeting card company.

It is not a reminder application.

It is not an AI writing assistant.

It is not a CRM.

It is not a calendar.

It is not a contact manager.

It is a premium Relationship Concierge.

Greeting cards happen to be the first service it provides.

Every future feature should reinforce this identity.

---

# Our North Star

Every product decision should answer one question.

> **What would a world class Relationship Concierge do here?**

If the answer is unclear, the feature should not be built until it is.

---

# Product Philosophy

Relationships are more important than features.

People are more important than technology.

Thoughtfulness is more important than automation.

Warmth is more important than efficiency.

Trust is more important than growth.

Quality is more important than speed.

Every experience should feel like thoughtful assistance from someone who genuinely cares.

---

# The User Experience We Want

Users should never feel like they are using software.

They should feel like they have someone quietly helping them remember what matters.

The experience should feel:

Calm.

Warm.

Personal.

Professional.

Helpful.

Trustworthy.

Premium.

Invisible.

The best interface is the one users barely notice.

---

# The Concierge Philosophy

A concierge never overwhelms.

A concierge never pressures.

A concierge never judges.

A concierge remembers.

A concierge notices.

A concierge recommends.

A concierge prepares.

A concierge quietly makes life easier.

That is the model every screen should follow.

---

# Relationship First

The unit of the product is not the card.

It is not the event.

It is not the reminder.

It is the relationship.

Everything revolves around people.

Every screen should help users better understand, strengthen, or celebrate a relationship.

---

# AI Philosophy

Artificial intelligence exists to reduce effort.

Not replace humanity.

AI should:

Help remember.

Help organize.

Help personalize.

Help communicate.

Help prepare.

Help celebrate.

The user always remains in control.

AI suggests.

Humans decide.

---

# Design Philosophy

The interface should feel premium without feeling luxurious.

Elegant without being flashy.

Simple without being empty.

Friendly without becoming childish.

Professional without becoming corporate.

Every interaction should feel effortless.

The design should disappear behind the experience.

---

# Visual Philosophy

The interface should feel calm.

Generous spacing.

Readable typography.

Warm colors.

Natural motion.

Minimal decoration.

Meaningful illustrations.

Purposeful animation.

Every visual decision should reduce stress rather than increase stimulation.

---

# Copy Philosophy

The product should sound like a thoughtful human.

Never robotic.

Never overly enthusiastic.

Never marketing driven.

Never guilt inducing.

The tone should be:

Warm.

Clear.

Respectful.

Encouraging.

Confident.

Human.

---

# Accessibility Philosophy

Accessibility is part of product quality.

Not an optional enhancement.

Every user deserves a first class experience regardless of ability.

Accessibility should be designed from the beginning.

Never added later.

---

# Trust Philosophy

Relationship data is among the most personal information someone owns.

Trust is our greatest competitive advantage.

Users should always understand:

Why information is collected.

How AI uses it.

How to edit it.

How to remove it.

How to export it.

Privacy should never become confusing.

---

# Business Philosophy

Professional relationships deserve the same level of care as personal ones.

Business users are not looking for another CRM.

They are looking for a better way to build authentic relationships.

The business experience should focus on people.

Not pipelines.

---

# Gamification Philosophy

Rewards should reinforce thoughtful behavior.

Never manipulate it.

Progress should celebrate consistency.

Not addiction.

The goal is stronger relationships.

Not longer screen time.

---

# Frontend Philosophy

The frontend should feel handcrafted.

Not assembled.

Every pixel should communicate intention.

Consistency is mandatory.

Every component should belong to a unified design system.

Nothing should feel accidental.

---

# Design System Principles

Consistency creates trust.

Predictability creates confidence.

Simplicity reduces cognitive load.

Spacing is part of communication.

Animation should clarify.

Typography should improve comprehension.

Color should communicate meaning.

Every component should exist for a reason.

---

# Performance Philosophy

Perceived speed matters as much as actual speed.

Users should always feel that the product is responsive.

Waiting should be rare.

Loading should feel intentional.

Animations should reduce perceived delay.

Every interaction should acknowledge user input immediately.

---

# Technical Philosophy

The backend is already successful.

Do not redesign it.

Preserve:

Database schema.

Business logic.

Authentication.

API contracts.

AI pipelines.

Stripe integration.

Handwrytten integration.

Everything in this playbook focuses on the frontend experience.

---

# Development Philosophy

Do not add features because competitors have them.

Do not redesign simply for novelty.

Do not optimize for trends.

Optimize for relationships.

Every line of code should improve the user experience.

---

# The Product Evolution Model

The platform evolves through three stages.

## Stage One

Remember important moments.

## Stage Two

Understand relationships.

## Stage Three

Proactively strengthen relationships.

Every future feature should clearly support one of these stages.

---

# Non Negotiable Rules

Never overwhelm users.

Never guilt users.

Never manipulate users.

Never surprise users with AI.

Never hide important actions.

Never sacrifice clarity for aesthetics.

Never introduce unnecessary complexity.

Never collect information without purpose.

Never break user trust.

Never forget that people matter more than software.

---

# Before Building Any Feature

Ask:

Does this strengthen relationships?

Does this reduce effort?

Does this make users more thoughtful?

Does it feel warm?

Does it respect privacy?

Does it reduce cognitive load?

Would a concierge do this?

If the answer is no, stop.

---

# Before Approving Any UI

Ask:

Is it obvious?

Is it beautiful?

Is it calm?

Is it accessible?

Is it fast?

Is it trustworthy?

Is it emotionally appropriate?

Would a first time user understand it?

Would an experienced user enjoy using it every day?

---

# Before Writing Any Copy

Ask:

Would a thoughtful human say this?

Is it warm?

Is it respectful?

Is it concise?

Does it avoid guilt?

Does it inspire confidence?

Does it sound premium?

---

# Before Adding AI

Ask:

Does AI reduce effort?

Does the user remain in control?

Can the recommendation be explained?

Can the user override it?

Does it improve relationships?

If not, AI should not be involved.

---

# Before Shipping Anything

Review:

Accessibility.

Performance.

Consistency.

Typography.

Spacing.

Motion.

Copy.

Error states.

Loading states.

Empty states.

Responsive behavior.

Dark mode compatibility.

Trust.

Privacy.

Emotional tone.

No feature is complete until all of these are complete.
