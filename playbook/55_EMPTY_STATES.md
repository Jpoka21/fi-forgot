# Empty States

---

# Purpose

Empty states are not placeholders.

They are conversations.

In most software, an empty state simply informs the user that nothing exists yet.

In F.I. Forgot, every empty state should reinforce one truth:

**Every meaningful relationship starts somewhere.**

An empty screen should never feel like a dead end.

It should feel like an invitation.

Every empty state should reassure the user, explain what comes next, reduce uncertainty, and provide a clear next step.

The user should never wonder:

*"Did something break?"*

Instead they should feel:

*"I'm exactly where I should be."*

---

# Empty State Philosophy

A Relationship Concierge never says:

"You don't have anything."

Instead it says:

"Let's build something meaningful together."

Every empty state should:

* explain why the page is empty

* remove anxiety

* reinforce progress

* encourage the next action

* avoid guilt

* feel optimistic

* celebrate beginnings

Empty states are part of onboarding even years after signup.

---

## Reassurance

---

## Progress

---

## Optimism

The future experience will become richer over time.

---

## Warmth

The interface should feel human instead of transactional.

---

## Curiosity

Encourage exploration without pressure.

---

## Confidence

The user should always know what to do next.

---

# Concierge Messaging Principles

Every message should sound like a thoughtful concierge.

Never sound like software.

Instead of:

"No recipients found."

Say:

"Let's add the first person who matters to you."

Instead of:

"No memories."

Say:

"The little stories you save today become tomorrow's unforgettable cards."

Instead of:

"No data available."

Say:

"We're just getting started."

---

## Voice Characteristics

Copy should always be:

* warm

* calm

* optimistic

* encouraging

* concise

* conversational

* emotionally intelligent

Never:

* robotic

* sarcastic

* passive aggressive

* technical

* overly clever

* apologetic without reason

---

# Illustration Philosophy

Illustrations should communicate emotion before information.

Every illustration should feel:

* handcrafted

* warm

* inviting

* optimistic

* premium

* timeless

Illustrations should reinforce relationships rather than software.

Preferred subjects include:

* handwritten notes

* envelopes

* people connecting

* conversations

* coffee

* celebrations

* small thoughtful moments

* memories

* gifts

* friendship

* family

* pets

Avoid:

* empty folders

* empty boxes

* warning symbols

* sad faces

* exaggerated cartoons

* error icons

Illustrations should feel hopeful.

Never lonely.

# Empty Settings Sections

Individual settings categories may not contain personalized information yet.

Instead of blank panels:

Explain:

* what belongs here

* why it matters

* when it will appear

Every settings page should educate before it configures.

---

# Offline Empty States

Offline should never feel broken.

Headline

You're offline right now.

Supporting copy

You can still browse previously loaded information. We'll sync everything once you're connected again.

Secondary CTA

# AI Related Empty States

Never expose implementation details.

Do not say:

"No AI output."

Instead say:

We're gathering everything needed to create something thoughtful.

Examples:

"We're learning more about this relationship."

"This card will become even more personal as we learn more."

"We need one or two more details before we can create something truly meaningful."

## Experienced User

# Accessibility Requirements

Every empty state must satisfy WCAG AA.

Requirements include:

* semantic headings

* screen reader support

* descriptive illustrations

* keyboard accessible buttons

* visible focus indicators

* minimum touch targets

* sufficient contrast

* no information conveyed only through illustration

* no animation required for understanding

Illustrations should include meaningful alternative text.

---

# Anti Patterns

Never use:

"No Data"

"Nothing Here"

"404"

"Empty"

"No Results Found"

"Database Empty"

"Coming Soon"

"No Records"

Do not blame users.

Do not create guilt.

Do not use error colors unless an actual error occurred.

Never leave users without an obvious next action.

Never use generic stock illustrations.

Never make an empty page feel abandoned.

---

# Review Checklist

Every empty state should answer:

□ Does this feel like a Relationship Concierge?

□ Does it reassure the user?

□ Is there a clear next step?

□ Does the illustration support the emotion?

□ Does the copy sound warm and human?

□ Is the layout visually balanced?

□ Is the CTA obvious?

□ Is accessibility fully supported?

□ Does the screen avoid guilt or pressure?

□ Does it encourage thoughtful relationships?

□ Would this experience still feel premium five years from now?

If every answer is yes, the empty state meets the F.I. Forgot standard.
