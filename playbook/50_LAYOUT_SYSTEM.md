# Layout System

---

# Purpose

The F.I. Forgot layout system defines how every screen is structured.

Its purpose is to make the product feel calm, premium, readable, and emotionally intelligent across every device.

Layout should never feel crowded.

Layout should never feel mechanical.

Layout should never feel like a dashboard for tasks.

F.I. Forgot is a Relationship Concierge.

The layout should make people, memories, moments, and thoughtful actions feel like the center of the experience.

Every layout decision should answer one question:

> **"Would a world class Relationship Concierge arrange the experience this way?"**

---

# Layout Philosophy

The layout system is built around restraint.

Most software tries to show everything at once.

F.I. Forgot should do the opposite.

It should reveal what matters.

It should reduce mental load.

It should guide the user toward one thoughtful next action.

The interface should feel spacious, warm, and composed.

The product should never feel like:

A CRM.

A reminder app.

A productivity dashboard.

A greeting card marketplace.

A writing tool.

A task manager.

The user should feel that the product is quietly organizing relationship care on their behalf.

---

# Relationship First Hierarchy

The layout hierarchy is always:

1. People

2. Important moments

3. Relationship context

4. Suggested thoughtful action

5. Supporting controls

This means people should appear before system mechanics.

Names should appear before scores.

Photos should appear before settings.

Moments should appear before buttons.

Relationship context should appear before configuration.

---

# Core Layout Principles

## One Primary Focus

Every screen should have one dominant focus.

Examples:

Dashboard

Who needs attention next?

Recipient profile

What matters about this person?

Card creation

What should this card say?

Settings

How should the concierge behave?

---

## Fewer Columns

Avoid dense multi column layouts.

Use columns only when they improve clarity.

Never create a dashboard wall.

---

## Spacious by Default

Space communicates calm and premium quality.

Tight spacing makes the product feel transactional.

---

## Content Before Controls

Controls should support the experience.

They should not lead it.

---

## Progressive Disclosure

Do not show every option at once.

Reveal details when they become useful.

---

## Mobile First Emotional Design

Mobile is not a compressed desktop.

Mobile should feel intimate, simple, and focused.

---

Grid should support layout consistency without making screens feel rigid.

# Vertical Rhythm

Vertical rhythm should feel editorial.

Headings need room.

Cards need breathing space.

Forms need calm progression.

Avoid stacking too many elements with equal spacing.

Important content should receive more space.

Supporting content should sit closer together.

---

# Horizontal Spacing

Horizontal spacing should prevent crowding.

Never place meaningful relationship content too close to the screen edge.

On mobile, maintain at least 16px padding.

On tablet, maintain at least 24px padding.

On desktop, maintain at least 32px padding.

Large desktop layouts should center content rather than stretch it.

---

# Page Templates

Every screen should begin from one of the core templates below.

Do not invent new page structures unless the product clearly requires it.

---

# Dashboard Layout

The dashboard should answer:

Who needs attention?

What matters soon?

What should I do next?

---

## Dashboard Structure

1. Warm welcome

2. Primary relationship prompt

3. Upcoming moments

4. Suggested thoughtful action

5. Relationship overview

6. Supporting concierge insights

---

## Dashboard Rules

Keep the dashboard emotionally focused.

Avoid KPI strips.

Avoid analytics first layouts.

Avoid showing too many cards at once.

Limit primary upcoming cards to three.

Make one next action visually clear.

Use whitespace to reduce urgency.

The dashboard should feel like a calm briefing, not a control room.

---

# Recipient Detail Layout

The recipient detail page is the emotional hub for one relationship.

It should answer:

Who is this person to me?

What do I know about them?

What has happened recently?

What should I remember?

What thoughtful action should I take?

---

## Recipient Detail Structure

1. Recipient identity header

2. Relationship context

3. Primary thoughtful action

4. Timeline or memory stream

5. Important dates

6. Relationship insights

7. Preferences and details

8. Secondary actions

---

## Recipient Detail Rules

The person always comes first.

Do not lead with settings.

Do not lead with scores.

Do not lead with data.

Memory and context should be easier to find than configuration.

---

# Card Creation Layout

Card creation should feel like working with a concierge, not filling out a form.

It should answer:

What are we creating?

Who is it for?

What should it feel like?

What personal context should be included?

What needs approval?

---

## Card Creation Structure

1. Recipient and occasion context

2. Concierge guidance

3. Draft or input area

4. Personalization context

5. Review controls

6. Delivery controls

---

## Card Creation Rules

Keep the writing experience focused.

Avoid sidebars on mobile.

Avoid too many simultaneous editing tools.

Show the card content prominently.

Use supporting context only when helpful.

The draft should feel precious.

---

# Form Layout

Forms should feel conversational.

They should not feel bureaucratic.

---

## Form Structure

1. Clear question or purpose

2. Brief explanation

3. Input

4. Helpful supporting text

5. Primary action

6. Optional secondary action

---

## Form Rules

One idea per section.

Use labels clearly.

Avoid long forms when a progressive flow would feel better.

Group related fields with generous spacing.

Never make personal questions feel like database entry.

---

# Wizard Layout

Wizard flows are used for onboarding, first conversation, setup, and guided card creation.

---

## Wizard Structure

1. Progress context

2. Human question

3. Short explanation

4. Input or choice

5. Continue action

6. Back or skip action when appropriate

---

## Wizard Rules

Progress indicators should reassure, not pressure.

Never overload one step.

Use warm copy.

Avoid making the user feel tested.

Skip should be available when the question is not essential.

---

# Empty State Layout

Empty states should feel helpful, not empty.

They should explain what the concierge will do next.

---

## Empty State Structure

1. Warm illustration or icon

2. Human headline

3. Reassuring explanation

4. One clear action

5. Optional softer secondary action

---

## Empty State Rules

Do not blame the user.

Do not say there is no data.

Do not make the product feel broken.

Use empty states to teach the product gently.

---

# Mobile Layout Principles

Mobile should feel intimate.

Users are likely checking quickly.

The layout must prioritize clarity and emotional ease.

---

## Mobile Rules

Use one column.

Avoid dense cards.

Avoid permanent sidebars.

Use bottom navigation when appropriate.

Keep primary actions thumb reachable.

Do not hide important relationship context behind too many taps.

Use sticky actions only when they reduce effort.

---

# Tablet Layout Principles

Tablet should use more space without becoming dense.

---

## Tablet Rules

Use one or two columns.

Keep emotional content dominant.

Avoid three column layouts.

Allow supporting panels only when they improve comprehension.

---

# Desktop Layout Principles

Desktop should feel composed.

It should not become a data dashboard.

---

## Desktop Rules

Use two columns carefully.

Use side panels sparingly.

Keep max widths.

Avoid stretching cards across the full viewport.

Make the main content area clearly dominant.

---

# Card Layouts

Cards are the primary layout unit of the product.

They should feel like pieces of thoughtful stationery.

---

## Card Rules

Use warm white surfaces.

Use subtle borders.

Use soft shadows only when needed.

Use generous internal padding.

Do not overcrowd cards.

One card should generally communicate one idea.

---

## Card Padding

Mobile

```

16px

```

Tablet

```

20px

```

Desktop

```

24px

```

```

32px
```

# Sidebar Rules

Sidebars should be used carefully.

They are supportive, not primary.

---

## Sidebar Uses

Context

Settings

Secondary navigation

Helpful concierge notes

---

## Sidebar Rules

Do not use sidebars on mobile.

Avoid placing primary actions only in sidebars.

Do not make sidebars visually heavier than the main content.

Collapse or stack sidebars on tablet when needed.

---

# Header Rules

Headers orient the user.

They should feel calm and useful.

---

## Header Structure

1. Page title

2. Human context

3. Primary action when needed

4. Secondary controls when needed

---

## Header Rules

Avoid oversized utility headers.

Avoid clutter.

Do not place too many actions in the header.

Use concise titles.

Let emotional context appear near the title when relevant.

---

# Footer Rules

Footers should stay quiet.

Most app screens do not need heavy footers.

Use footers for:

Legal links

Help

Trust information

Secondary brand reassurance

Never use footer space for primary product actions unless the screen requires a sticky action area.

---

# Sticky Element Rules

Sticky elements should reduce effort.

They should not create pressure.

---

## Allowed Sticky Elements

Mobile primary action bar

Card review approval controls

Wizard continue button

Important save controls

---

## Sticky Rules

Use sparingly.

Never stack multiple sticky bars.

Ensure sticky elements do not block content.

Use warm surfaces and subtle borders.

---

# Responsive Behavior

Responsive behavior should preserve hierarchy.

It should not merely shrink components.

---

## Desktop to Tablet

Reduce columns.

Stack supporting panels below main content.

Preserve primary action visibility.

---

## Tablet to Mobile

Move to one column.

Simplify secondary controls.

Convert sidebars into sections.

Use bottom sheets only when helpful.

---

## Mobile to Desktop

Do not simply spread content.

Add breathing room.

Keep reading widths.

Use secondary panels only when meaningful.

---

# Density Guidelines

F.I. Forgot should use low to medium density.

High density is reserved only for admin or operational views.

---

## Low Density

Used for:

Onboarding

Card creation

Recipient profile

Empty states

Emotional moments

---

## Medium Density

Used for:

Dashboard

Settings

Lists

Navigation

---

## High Density

Avoid in customer facing areas.

May be acceptable for internal admin tools only.

---

# Alignment Rules

Use left alignment for most content.

Center alignment may be used for:

Empty states

Onboarding moments

Success moments

Hero sections

Avoid centered long paragraphs.

Avoid mixing too many alignment styles on one screen.

---

# White Space Philosophy

White space is not wasted space.

It creates trust.

It creates calm.

It makes personal content feel important.

F.I. Forgot should use white space the way luxury brands use silence.

Purposefully.

Confidently.

Generously.

---

# Scanning Patterns

Users should be able to scan every screen quickly.

The layout should support:

Clear headings

Short sections

Distinct cards

Visible primary actions

Readable groupings

Calm progression

Avoid walls of equal weight content.

---

# Visual Hierarchy

Visual hierarchy should be created through:

Size

Spacing

Placement

Typography

Surface

Then color

Color should not carry the hierarchy alone.

# Layout Anti Patterns

Avoid:

Crowded dashboards.

KPI strips.

Too many equal cards.

Full width text on desktop.

Dense settings pages.

Three column customer layouts.

Floating controls everywhere.

Primary actions hidden in menus.

Important people presented like records.

Relationship memories presented like logs.

Huge colorful banners.

Overuse of sticky elements.

Excessive nested cards.

Sidebars that compete with content.

Mobile layouts that feel compressed instead of designed.

---

# Review Checklist

Before approving any layout, verify:

□ Is there one clear primary focus?

□ Does the person or relationship come before system mechanics?

□ Is the layout calm?

□ Is there enough white space?

□ Is the content readable?

□ Is the hierarchy obvious?

□ Are controls supportive rather than dominant?

□ Does the mobile version feel intentionally designed?

□ Is the desktop version restrained?

□ Are max widths respected?

□ Are forms conversational rather than bureaucratic?

□ Are empty states helpful and warm?

□ Are sidebars used only when helpful?

□ Are sticky elements necessary?

□ Does the screen avoid dashboard density?

□ Would this layout feel appropriate for a premium Relationship Concierge?

If the answer to any question is no, the layout should be revised before implementation.
