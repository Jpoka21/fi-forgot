# Settings Experience

## Purpose

Most applications treat Settings as a storage room.

As features are added over time, new switches, checkboxes, and menus are placed into Settings until it becomes a confusing collection of technical options.

A world class Relationship Concierge should never require its users to constantly configure how it behaves.

Its responsibility is to understand the user through observation, learning, and thoughtful defaults.

Settings therefore exist for one purpose:

To provide transparency, control, and trust.

They should never exist because the concierge failed to make a good decision.

Every setting should answer one question:

**"Is this something the user genuinely wants control over?"**

If the answer is no, the concierge should make the decision intelligently.

The fewer settings a user ever touches, the better the concierge is doing.

---

# Settings Philosophy

The Relationship Concierge should feel personal before it feels configurable.

It should learn instead of asking.

Adapt instead of requiring setup.

Improve instead of demanding maintenance.

Settings are therefore not where the concierge becomes intelligent.

Settings are where the concierge explains itself and gives the user final control.

A great concierge quietly handles thousands of decisions without requiring permission for every one.

The user should feel empowered, never burdened.

---

# Core Principles

Every setting should follow these principles.

## Intelligent by Default

Every feature should work well before the user changes anything.

Default behavior should represent the experience that benefits the largest majority of users.

Customization exists to refine an already excellent experience, not to repair a poor one.

---

## Explain Before Asking

Whenever possible, the concierge should explain why something exists before asking the user to configure it.

People are far more comfortable adjusting behavior they understand.

---

## Progressive Complexity

New users should see only the controls that matter.

Advanced options should appear only when appropriate.

Most users should never feel overwhelmed by configuration.

---

## Human Language

Settings should never read like software documentation.

Avoid technical terminology whenever possible.

Instead of:

"Notification Frequency"

Prefer:

"How often would you like to hear from your concierge?"

Instead of:

"AI Personalization"

Prefer:

"How much should I personalize your cards?"

The language should sound like a conversation.

---

## Trust Before Convenience

Whenever convenience conflicts with trust, trust wins.

The concierge should always choose the option that strengthens the user's confidence, even if it requires an extra confirmation.

---

# The Role of Settings

Settings are not where users operate the concierge.

They are where users build trust with it.

Every screen should answer one of four questions.

Who can see my information?

How does the concierge communicate?

How does the concierge learn?

How is my account managed?

Everything else should happen automatically.

---

# Settings Organization

Settings should be organized around people rather than technology.

The recommended sections are:

## My Concierge

This section explains how the concierge works.

It includes:

Communication style.

Notification preferences.

Planning preferences.

Relationship coaching.

Memory suggestions.

Proactive assistance.

Digest frequency.

Learning preferences.

The focus is not on enabling features.

The focus is on shaping the concierge's personality.

---

## Relationships

This section manages how relationships are handled.

Examples include:

Default reminder preferences.

Household behavior.

Shared relationships.

Relationship visibility.

Archived relationships.

Importing contacts.

Relationship categories.

The concierge should make clear that relationships belong to the user.

Not the application.

---

## Privacy & Trust

This is one of the most important sections in the product.

It should explain:

What information is stored.

How memories are used.

How AI personalizes cards.

Who can access information.

How data is protected.

How to delete memories.

How to export information.

Connected services.

Security.

The goal is complete transparency.

Users should never wonder what the concierge knows about them.

---

## Notifications

Notification controls should be written in relationship language rather than technical language.

Examples include:

When should I remind you?

How would you like to hear from me?

Should I combine reminders whenever possible?

Should I avoid evenings?

Should I text you only for urgent situations?

Users should feel like they are instructing an assistant.

Not configuring software.

---

## Account

Traditional account management belongs here.

Including:

Email.

Password.

Authentication.

Subscription.

Billing.

Payment methods.

Shipping addresses.

Connected accounts.

Business workspace.

Household membership.

Legal information.

These items should remain clean and conventional.

There is no need to reinvent account management.

---

# Smart Defaults

The concierge should assume responsibility whenever possible.

Examples:

Instead of asking:

"When would you like birthday reminders?"

The concierge should automatically determine appropriate timing.

Instead of asking:

"How often should we ask about memories?"

The concierge should learn from user engagement.

Instead of asking:

"What communication channel do you prefer?"

The concierge should observe response behavior.

Instead of asking:

"What relationship deserves priority?"

The concierge should infer importance naturally.

Settings should exist only when observation cannot produce a reliable answer.

---

# Notification Preferences

Users should always have complete control over interruptions.

However, controls should be simple.

Preferred categories include:

Important relationship moments.

Card approvals.

Shipping updates.

Weekly summaries.

Monthly relationship insights.

Relationship coaching.

Memory prompts.

Seasonal planning.

Communication methods should be adjustable separately for:

Push notifications.

Email.

SMS.

In app messages.

The concierge should clearly explain the purpose of each channel.

---

# AI Transparency

The concierge should never behave like a mysterious black box.

Users deserve to understand how personalization works.

The settings experience should explain:

How memories influence cards.

How conversations improve personalization.

How preferences evolve.

What AI remembers.

What AI never remembers.

How to remove information.

How to reset personalization.

Users should always feel in control.

Understanding creates trust.

---

# Memory Controls

Memories are among the most valuable assets inside F.I. Forgot.

Users should have simple controls to:

Review memories.

Edit memories.

Delete memories.

Pin important memories.

Archive memories.

Correct inaccurate information.

Merge duplicates.

View memory history.

Nothing should feel permanent.

Relationships evolve.

The concierge should evolve with them.

---

# Privacy Philosophy

Relationship information is deeply personal.

The concierge should treat every memory as if it had been shared in confidence.

Privacy should therefore be proactive.

Not reactive.

The product should clearly communicate:

We never sell your relationship information.

We never use your memories for advertising.

We never expose your relationships publicly.

We never share personal stories without your permission.

Trust should never require reading legal documents.

The product itself should communicate these values.

---

# Data Ownership

Every relationship belongs to the user.

Every memory belongs to the user.

Every story belongs to the user.

The concierge is a steward.

Not an owner.

Users should always be able to:

Export their data.

Delete their data.

Transfer their information.

Download memories.

Remove connected accounts.

Leave without penalty.

The best products make leaving easy.

Confidence that users can leave often makes them stay.

---

# Connected Services

Integrations should exist to reduce effort.

Not increase complexity.

Connections may include:

Calendar providers.

Address books.

Email.

Handwrytten.

Payment providers.

Business CRMs.

Future relationship services.

Every connection should clearly explain:

Why it exists.

What data is shared.

What data is never shared.

How to disconnect it.

No integration should ever feel hidden.

---

# Subscription & Billing

Billing should be simple.

Predictable.

Transparent.

Users should always understand:

Their current plan.

Upcoming renewals.

Included benefits.

Card usage.

Additional charges.

Shipping costs.

Billing history.

Upgrade options.

Cancellation.

Downgrades.

Nothing should require contacting support.

Trust grows when billing is obvious.

---

# Accessibility

Accessibility should not be treated as an advanced feature.

It should be part of the concierge's promise to every user.

Settings should provide clear controls for:

Text size.

Contrast.

Motion reduction.

Voice support.

Language.

Notification accessibility.

Screen reader optimization.

These controls should be easy to discover.

Not buried.

---

# What Should Never Be a Setting

Some decisions belong to the concierge.

Examples include:

AI confidence thresholds.

Card quality standards.

Writing quality.

Relationship scoring methodology.

Memory organization.

Suggestion ranking.

Background learning cadence.

Performance optimization.

Internal system behavior.

These are product decisions.

Not user decisions.

The concierge should continuously improve these without requiring user involvement.

---

# The Feeling of Settings

A user should leave Settings with one overwhelming impression:

"I understand how my concierge works."

Not:

"I finished configuring another app."

The experience should reinforce confidence.

It should communicate care.

It should demonstrate transparency.

It should quietly remind the user that they remain in control.

---

# Guiding Principles

When designing Settings, every decision should support these principles.

* Fewer settings create a better concierge.

* Defaults should be intelligent.

* Transparency builds trust.

* Users should always control their own information.

* Settings should explain, not confuse.

* Privacy should be obvious.

* AI should be understandable.

* Customization should refine, never repair.

* Relationship information is sacred.

* Every control should earn its place.

* The concierge should do the work.

* Trust is the most important setting of all.
