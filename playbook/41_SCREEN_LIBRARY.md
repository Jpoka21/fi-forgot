# 41_SCREEN_[LIBRARY.md](http://LIBRARY.md)

## Purpose

This document defines the complete screen library for the redesigned F.I. Forgot frontend.

It identifies the primary product screens, their purpose, the user intent they serve, the actions they support, and the adjacent experiences they connect to.

This document is not a wireframe.

This document is not a technical routing file.

This document is not an implementation specification.

It is the canonical inventory of product surfaces that make up F.I. Forgot as a premium Relationship Concierge.

Every screen should answer one question:

**What would a world class Relationship Concierge do here?**

---

## Screen Library Philosophy

F.I. Forgot should feel like one connected experience.

Users should never feel like they are jumping between unrelated tools.

Every screen should reinforce the same product truth:

F.I. Forgot helps people become more thoughtful in the relationships that matter most.

Screens should be organized around user intent, not internal system structure.

The product should feel calm, guided, emotionally intelligent, and trustworthy.

The screen library should prevent unnecessary screen sprawl.

New screens should only be added when they clarify the experience, reduce complexity, or support a meaningful relationship action.

---

## Screen Categories

The redesigned product includes the following screen categories:

1. Public Screens
2. Authentication Screens

Each category should feel connected to the same brand, voice, and emotional architecture.

# Screen Addition Rules

New screens should only be added when they satisfy at least one of the following conditions:

1. They make a major user intent clearer.
2. They reduce complexity on an existing screen.
3. They create a calmer or more guided experience.
4. They support a meaningful relationship action.
5. They are required by existing functionality.
6. They improve trust, privacy, accessibility, or recovery.

New screens should not be added simply because a feature exists.

A feature can often live inside an existing screen, section, card, modal, or Concierge prompt.

The product should avoid becoming fragmented.

---

# Screen Quality Rules

Every screen must have:

1. A clear purpose.
2. A clear primary user.
3. One obvious primary action.
4. Relationship context when relevant.
5. Calm visual hierarchy.
6. Human copy.
7. Useful empty states.
8. Recoverable errors.
9. Accessible structure.
10. A clear connection to the Relationship Concierge philosophy.

If a screen cannot explain why it exists, it should not exist.

---

# Guiding Principles

The screen library should keep F.I. Forgot focused.

The product is not a CRM.

It is not a greeting card catalog.

It is not a reminder app.

It is not an AI writing workspace.

It is a premium Relationship Concierge.

Screens should be few enough to feel simple.

Rich enough to feel capable.

Connected enough to feel coherent.

Warm enough to feel human.

Every screen should help the user become more thoughtful in the relationships that matter most.

Every screen should answer:

**What would a world class Relationship Concierge do here?**
