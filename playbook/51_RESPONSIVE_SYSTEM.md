# Responsive System

---

# Purpose

The F.I. Forgot responsive system ensures that every experience feels intentionally designed on every device.

Responsive design is not about shrinking desktop screens to fit smaller displays.

It is about preserving the emotional experience regardless of screen size.

Whether someone opens F.I. Forgot on a phone while waiting in line, on a tablet from the couch, or on a desktop while planning upcoming cards, the experience should always feel calm, premium, thoughtful, and effortless.

Every responsive decision should answer one question:

> **"Would a world class Relationship Concierge present this experience this way on this device?"**

---

# Responsive Philosophy

Every device has different strengths.

Mobile excels at focus.

Tablet excels at browsing.

Desktop excels at organization.

Rather than forcing identical layouts across every screen, the interface should adapt to each environment while preserving hierarchy, emotional tone, and usability.

The user should never feel that features were removed or awkwardly squeezed.

Every layout should feel native to the device.

---

# Mobile First Philosophy

Design begins with mobile.

If the experience works beautifully on a phone, it can gracefully expand to larger screens.

Do not begin with desktop and compress downward.

Start with the smallest meaningful experience.

Then progressively enhance.

---

# Core Responsive Principles

## Preserve Hierarchy

The order of importance never changes.

People remain first.

Relationships remain first.

Memories remain first.

Only the presentation changes.

---

## Simplify Before Shrinking

Never reduce everything proportionally.

Instead:

Reduce complexity.

Stack sections.

Hide secondary controls.

Prioritize content.

---

## One Clear Primary Action

Regardless of screen size, users should always understand the next thoughtful action.

---

## Reading Comfort Always Wins

Large screens should never create extremely wide reading columns.

Comfortable reading width is more important than using available space.

---

## Emotional Consistency

Every screen should feel equally warm on every device.

Never allow responsive changes to create a colder experience.

---

# Breakpoint Strategy

## Mobile

```

0px – 767px

```

Primary experience.

Single column.

Touch first.

---

## Tablet

```

768px – 1023px

```

Expanded browsing.

Optional second column.

Larger touch targets.

---

## Desktop

```

1024px – 1439px

```

Two column layouts.

Additional context panels.

Improved comparison.

---

## Large Desktop

```

1440px+

```

Additional whitespace.

Never additional complexity.

Content remains centered.

---

# Fluid Scaling

Rather than jumping dramatically between breakpoints, spacing and typography should scale smoothly whenever possible.

Padding, margins, and spacing should increase gradually.

Large visual jumps should be avoided.

---

# Responsive Typography

Typography should remain readable without dramatically changing personality.

### Mobile

Compact.

Easy to scan.

Comfortable line lengths.

---

### Tablet

Slightly larger hierarchy.

Improved spacing.

---

### Desktop

Additional breathing room.

No oversized headlines.

---

### Rules

Maintain approximately 60 to 75 characters per reading line.

Avoid long paragraphs spanning the full screen.

---

# Responsive Spacing

Spacing should increase as screen size grows.

The goal is breathing room, not emptiness.

### Mobile

16px outer padding.

---

### Tablet

24px outer padding.

---

### Desktop

32px outer padding.

---

### Large Desktop

40 to 48px outer padding.

Content remains centered.

Bottom navigation.

Simple.

Persistent.

Maximum five primary destinations.

Secondary navigation appears within pages.

---

## Tablet

Sidebar or bottom navigation depending on orientation.

Navigation should never dominate the screen.

---

## Desktop

Persistent sidebar.

Compact.

Emotionally quiet.

Focused on people rather than system tools.

---

### Mobile

Title.

Primary action.

Minimal controls.

---

### Tablet

Additional supporting information when helpful.

---

### Desktop

Title.

Supporting context.

Primary action.

Secondary controls.

Never overcrowded.

# Responsive Sidebars

### Mobile

No persistent sidebar.

Sidebar content becomes stacked sections or bottom sheets.

---

### Tablet

---

Persistent secondary sidebar when beneficial.

Must never compete with primary content.

# Responsive Cards

Cards should preserve generous spacing on every device.

### Mobile

Single column.

Full width.

Readable.

---

### Tablet

One or two columns.

---

### Desktop

Grid only when it improves comprehension.

Avoid excessive horizontal scanning.

---

# Responsive Forms

Forms should always feel conversational.

### Mobile

Single column.

Large touch targets.

Generous spacing.

---

### Tablet

Single column preferred.

Occasional paired fields.

---

### Desktop

Limited two column layouts.

Only when relationships between fields are obvious.

Never create large data entry grids.

---

# Responsive Tables

Customer facing tables should be minimized.

Whenever possible:

Convert tables into cards on smaller screens.

Relationship information should never feel spreadsheet driven.

---

# Responsive Timeline

### Mobile

Vertical timeline.

Single stream.

Large touch targets.

---

### Tablet

Vertical timeline with additional metadata.

---

### Desktop

Primary timeline with optional supporting detail panel.

---

### Mobile

Timeline.

Actions.

Relationship details.

Settings.

---

### Tablet

---

### Desktop

Primary timeline.

Supporting context panel.

Relationship information remains dominant.

---

# Responsive Dashboard

### Mobile

One continuous flow.

Welcome.

Upcoming moments.

Suggested action.

Relationship updates.

---

### Tablet

Upcoming moments remain primary.

---

### Desktop

Main content with supporting insights.

Never exceed two primary columns.

---

# Responsive Onboarding

Always maintain conversational pacing.

Questions remain full width.

Illustrations scale proportionally.

Never reduce emotional space simply because the screen is smaller.

---

# Responsive Card Creation

### Mobile

Writing experience dominates.

Supporting tools hidden until needed.

---

### Tablet

Preview beside editor when space allows.

---

### Desktop

Editor with supporting relationship context.

Preview remains prominent.

---

# Responsive Illustrations

Illustrations should scale gracefully.

Never become decorative wallpaper.

If necessary, reduce illustration size before reducing readable content.

Illustrations may disappear before important content does.

---

# Responsive Images

Images should preserve aspect ratio.

Avoid aggressive cropping.

Recipient photos should always remain recognizable.

Card artwork should remain legible.

---

# Responsive Touch Targets

Minimum touch target:

```

44 × 44px

```

Preferred:

```

48 × 48px

```

Spacing between touch targets should prevent accidental taps.

---

# Responsive Gestures

Gestures should enhance interaction.

Never replace discoverable controls.

Supported gestures include:

Swipe cards.

Dismiss notifications.

Scroll timelines.

Drag within appropriate editors.

Every gesture should have a visible alternative.

---

# Landscape Behavior

Landscape layouts should prioritize readability.

Do not simply split everything into two columns.

Maintain emotional focus.

Avoid tiny text.

---

# Tablet Specific Patterns

Tablets encourage browsing.

Support richer exploration without increasing cognitive load.

Appropriate enhancements include:

Larger relationship cards.

Side by side comparisons.

Expanded timelines.

Persistent contextual information.

---

# Large Desktop Behavior

Large monitors should feel elegant.

Additional width becomes whitespace.

Never additional clutter.

Do not introduce more columns simply because space exists.

The interface should feel intentionally restrained.

---

# Foldable Device Considerations

Foldable devices should behave like tablets when expanded.

Single column experiences should gracefully become dual pane layouts where appropriate.

Avoid placing important controls across fold boundaries.

---

# Zoom and Browser Scaling

The interface must remain usable at:

100%

125%

150%

200%

No content should become inaccessible.

No controls should overlap.

No horizontal scrolling should appear during normal use.

---

# Performance Considerations

Responsive design should improve performance, not reduce it.

Recommendations:

Load appropriately sized images.

Lazy load illustrations below the fold.

Avoid unnecessary animation on lower powered devices.

Minimize layout shifts.

Prioritize meaningful content first.

---

# Orientation Changes

Switching between portrait and landscape should preserve user progress.

Forms should never reset.

Drafts should never disappear.

Scroll position should remain stable whenever possible.

---

# Adaptive Content Prioritization

When screen space becomes limited:

Hide decoration before functionality.

Hide secondary actions before primary actions.

Collapse supporting information before removing relationship context.

Never hide the primary thoughtful action.

---

# Accessibility Considerations

Responsive layouts must maintain:

Readable typography.

Touch friendly controls.

Keyboard accessibility.

Screen reader order.

Visible focus indicators.

Adequate spacing.

Color contrast.

Changing layouts must never change reading order for assistive technologies.

---

Every production screen should be tested on:

Small phone.

Large phone.

Tablet portrait.

Tablet landscape.

Laptop.

Desktop.

Large desktop.

Keyboard only navigation.

Screen reader.

200 percent zoom.

Dark mode.

Light mode.

Slow network.

Reduced motion enabled.

---

# Responsive Anti Patterns

Never:

Scale everything proportionally.

Use tiny tap targets.

Hide primary actions.

Stretch text across the screen.

Create three column customer layouts.

Overcrowd dashboards.

Depend on hover interactions.

Assume landscape orientation.

Remove relationship context.

Hide important memories.

Replace clear navigation with gestures alone.

Use responsive behavior that changes meaning.

Treat mobile as a reduced experience.

---

# Review Checklist

Before approving any responsive implementation, verify:

□ Does every screen feel intentionally designed on every device?

□ Does the hierarchy remain consistent?

□ Are people always prioritized over system controls?

□ Are reading widths comfortable?

□ Are touch targets large enough?

□ Does mobile feel focused rather than compressed?

□ Does desktop add breathing room instead of complexity?

□ Are sidebars used appropriately?

□ Are forms still conversational?

□ Are timelines readable?

□ Are recipient profiles emotionally engaging?

□ Are illustrations responsive without overwhelming content?

□ Are orientation changes handled gracefully?

□ Is keyboard navigation preserved?

□ Does the experience remain accessible at 200 percent zoom?

□ Does performance remain smooth on lower powered devices?

□ Does every responsive decision reinforce the feeling of a premium Relationship Concierge?

If the answer to any question is no, the responsive implementation should be revised before development is considered complete.
