Implement the Fresh Update system exactly as described below.

GOAL

Once a recipient's profile reaches 100% completion, the profile question engine should automatically transition into an ongoing Fresh Update mode.

The purpose is to keep recipient data current over months and years without modifying or replacing the original profile information.

This is a new layer of memory, not a replacement for the profile system.

---

CORE CONCEPT

The recipient profile now has two memory layers:

Layer 1: Permanent Profile

The existing 13 profile fields.

Examples:

Favorite memories
Personality traits
Communication style
Relationship details
Family details
Important preferences

These remain unchanged.

Layer 2: Fresh Updates

Recent information that changes over time.

Examples:

Recent accomplishments
Current challenges
New hobbies
Family developments
Things they are excited about

Fresh Updates are additive and historical.

Never overwrite previous updates.

---

Create a new constant:

FRESH_UPDATE_BANK

---

ROTATION LOGIC

Fresh Update mode activates automatically when:

profileCompletion === 100%

The profile question card remains visible.

It does not disappear.

Instead:

questionMode = "fresh_update"

Question selection logic:

Find the Fresh Update category that:

Has never been answered

OR

Has the oldest answer date

Return that question.

After all seven categories have answers:

Continue cycling forever.

Always select the category whose latest answer is oldest.

This guarantees:

Fresh updates never run out.
The database continuously grows.
The system naturally refreshes stale information.
